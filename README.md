# ReviewShield: detecting AI-generated product reviews

Fake reviews mislead shoppers and are now cheap to produce with language models. ReviewShield scores a review with **P(AI-generated)** and acts on that score like a real moderation system would:

- **Confident cases are decided automatically.** Each automatic decision has a chosen precision (99% by default).
- **Uncertain cases go to a human moderator.**

There are two detectors:

| Detector | Why |
|---|---|
| **TF-IDF + logistic regression** (calibrated) | Strong, fast, explainable baseline. Shows which words drove the score. |
| **DistilBERT** (fine-tuned) | Transformer that reads context, not just word counts. |

It also includes a **robustness test on reviews written by newer LLMs** than the one used for training, which is where AI-text detectors usually break.

## How it works

```
review ─► detector ─► P(generated) ─┬─ ≤ t_low   → Human          (automatic)
                                    ├─ ≥ t_high  → AI-generated   (automatic)
                                    └─ otherwise → Needs review   (moderator)
```

**Data:** [Fake Reviews Dataset](https://www.kaggle.com/datasets/mexwell/fake-reviews-dataset) (Salminen et al., 2022).
- 40K Amazon reviews across 10 categories: half original, half generated with GPT-2.
- Exact duplicates are removed before a stratified 70/15/15 split, so no review appears in two splits.

**TF-IDF + LR:**
- Word 1–2-grams, with stop words kept, because function words are a strong signal of machine text.
- Probabilities calibrated by Platt scaling with 5-fold CV, so the scores can be read as probabilities.

**DistilBERT:**
- `distilbert-base-uncased`, fine-tuned for 2 epochs: AdamW, linear warm-up and decay, mixed precision, 256 tokens.
- The epoch kept is the one with the best validation PR-AUC.

**Review zone** (`src/models/review_zone.py`):
- `t_high` is the lowest score at which flagged reviews are still ≥ 99% truly generated, measured on validation.
- `t_low` is the same rule for the "human" side.
- Everything in between goes to a moderator.
- This is *selective classification*: the system trades coverage for reliability, and the trade-off is measured on the test set.

**Error analysis** (`src/models/analyze_ood.py`):
- Score distributions on the new-generator data.
- Accuracy by review length, including how many reviews are truncated at 256 tokens.
- The 50 most confident mistakes of each model.

## Reproduce

```bash
pip install -r requirements.txt

# Data: put the Kaggle CSV at data/raw/fake reviews dataset.csv
python -m src.data.make_dataset          # clean + deduplicate
python -m src.data.make_splits           # 70/15/15 stratified split

python -m src.models.train_baseline      # TF-IDF + LR, about 1 min on CPU
python -m src.models.train_transformer   # DistilBERT, GPU recommended (Colab T4: about 5 min per epoch)

python -m src.models.evaluate            # test metrics for every trained model
python -m src.models.review_zone --model tfidf_lr
python -m src.models.review_zone --model distilbert

# Robustness on newer LLMs (optional external data)
python -m src.models.evaluate_external --data data/external/aigen-foodreview/data/test.csv --name aigen_foodreview
python -m src.models.analyze_ood

python -m pytest -q                      # tests run on synthetic data, no download needed
```

## Layout

```
src/common.py                    paths, label map, I/O, metrics
src/data/make_dataset.py         raw CSV -> cleaned parquet
src/data/make_splits.py          deduplicated stratified split
src/models/train_baseline.py     calibrated TF-IDF + logistic regression
src/models/train_transformer.py  DistilBERT fine-tuning
src/models/scorers.py            one scoring interface for both models (+ TF-IDF explanations)
src/models/evaluate.py           in-domain test metrics
src/models/review_zone.py        automatic / human-review thresholds
src/models/evaluate_external.py  zero-shot test on newer generators
src/models/analyze_ood.py        error analysis by length and confidence
src/ui/app.py, src/api/main.py   Streamlit demo, FastAPI service
tests/                           pipeline tests on synthetic data
```

## Limitations

- **Older generator:** the generated half of the training data comes from GPT-2. Text from modern LLMs is more fluent and harder to detect. The robustness section measures this instead of hiding it.
- **What the model actually learns:** it detects *generated text*, not every kind of fraudulent review. A human paid to write fake reviews is out of scope.
- **Next steps:**
  - Fine-tune on a mix of generators.
  - Add behavioural signals (reviewer history, timing bursts) for coordinated campaigns.
